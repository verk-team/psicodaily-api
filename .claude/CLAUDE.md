# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

PsicoDaily API: Flask backend (Portuguese codebase) for a mental-health platform connecting patients (`PACIENTE`) with professionals (`PSICOLOGO`, `PSIQUIATRA`). Frontend: `psicodaily-front` (Vercel, Vite on :5173).

## Claude files

Everything Claude-related lives in `.claude/`: this file, `architecture.md`, `plans/` (sprint plans), `decisions/` (decisions and postponed work), `skills/` (real folders, not symlinks), `skills-lock.json` and `install.cmd` (Claude Code installer for CMD). Don't create Claude docs, skills or config at the repo root or in `.agents/`. `.claude/` is excluded from the Docker image (`.dockerignore`).

## Commands

- Install: `pip install -r requirements.txt` (venv in `.venv`). Copy `.env.example` to `.env`.
- Dev (WSL): `./run.sh` runs gunicorn gthread with one process on 127.0.0.1:8000 and :8001.
- Dev (Windows, no WSL/Docker): Firebird 4 runs as the `FirebirdServerDefaultInstance` service (SYSDBA/`sysdba`). Run `.venv\Scripts\python app.py` (Flask dev server, threaded, port 5000; gunicorn doesn't run on Windows). In `.env`, `DB_DATABASE` is the absolute path to `database/BANCO.FDB`. Fresh local database with fake data: point `DB_DATABASE` to a new path and run `.venv\Scripts\python database/migrar.py --criar --seed database/seed.sql`. An existing local database without `SCHEMA_MIGRATION` needs `migrar.py --baseline 1` once. Leave `ENDPOINT_URL` commented out until you have real R2 keys: the `<account-id>` placeholder crashes boto3 at import.
- Docker: the image has Firebird 4 and the code, never a `.FDB` (`.dockerignore`). `docker-entrypoint.sh` runs, in order: (if `DB_DATABASE`, default `/data/BANCO.FDB`, is missing) create it only when `CRIAR_BANCO=1`, otherwise exit 1; start Firebird; reset the SYSDBA password to `DB_PASSWORD`; `gbak` to `/data/backups` (last 5 kept); `migrar.py`; gunicorn on :8000. Local run: `docker run -v <volume>:/data -e DB_PASSWORD=... -e CRIAR_BANCO=1 ...`.
- **Production runs on a Hostinger VPS** (KVM 2, Debian 13, since 2026-11-10; the Northflank account was abandoned without migrating data, so the `northflank` skill is obsolete). `docker-compose.yml` in `/opt/psicodaily-api`: service `api` (image `cavalliniph/psicodaily-api`, Firebird inside) and `caddy` (HTTPS for `api.psicodaily.tech`, see `Caddyfile`, certificates in the `caddy-data` volume). Database in the named volume `firebird-data` at `/var/lib/firebird/data` (`DB_DATABASE=/var/lib/firebird/data/BANCO.FDB`), gbak backups in `/var/lib/firebird/data/backups`. Only 80/443 are public: Docker bypasses the firewall, so the API port is bound to `127.0.0.1` and 3050 is never published. Never run two containers on the same `.FDB` (no replicas, no blue/green). `.env` exists only on the VPS. Deploy: push a `release/*` branch → `.github/workflows/deploy.yml` builds and pushes the image (`latest` and the commit SHA), SSHes into the VPS, checks out that commit and runs `docker compose up -d --wait`. There is no off-server backup yet.
- Tests: pytest (`pytest.ini` at the root). They need Firebird running and the fake users of `database/seed.sql` (22 psicólogo, 23 and 25 pacientes, 24 psiquiatra, 26 admin), and undo whatever they create. Run all with `.venv\Scripts\python -m pytest`, one file with `-m pytest tests/test_rotas.py`, one test with `-k nome`. `tests/apoio.py` has the IDs and helpers (`executar`, `cliente`, `checar`); `tests/conftest.py` has the fixtures: one client per role (`anonimo`, `paciente`, `profissional`, ...), cleanup lists (`sessoes`, `encaminhamentos`), `ultima_notificacao`, `agenda_vazia`, and the autouse `ultima_auditoria`, which deletes the AUDITORIA rows each test creates. New data a test creates goes in a yield fixture, never in a bare try/finally. `.github/workflows/ci.yml` runs `pytest` on every push and PR against a database built from zero. `tests/test_rotas.py` pins status and keys of every route: keep it green on refactors.

## Architecture

Full map (routes, data model, flows, known risks) in [architecture.md](architecture.md). Read it before touching cross-cutting code, and update it when routes, tables or infra change.

- **Layers (decided 2026-10-19)**: `view/` is HTTP only: it parses the request, calls a service and returns `jsonify`. No SQL and no `get_connection` there. Business rules, SQL and external APIs go in `services/<dominio>_service.py` as plain functions that never import from `flask` (`flask_bcrypt` is fine). Rule violations raise `ErroNegocio(msg, status, **extra)`, which `app.py` turns into `{'error': msg, **extra}`. Unexpected exceptions are logged and become a generic 500, so routes have no try/except. Rationale in architecture.md.
- `app.py` registers one Blueprint per domain from `view/*.py` (auth, usuarios, registros, prontuario, profissionais, consultas, encaminhamentos, pagamentos, artigos, favoritos, admin, notificacoes, lista_espera, dashboard, chat, assistente, whatsapp, assinaturas, signaling). Routes live under `/api/...`.
- **Database**: Firebird via `fdb`, raw SQL only (no ORM). **Schema = `database/migrations/NNNN_descricao.sql`**, applied in order by `database/migrar.py` and tracked in `SCHEMA_MIGRATION`; `0001_inicial.sql` is the production baseline. Rules: never edit an applied migration (add a new one); only additive changes per deploy (new nullable/defaulted column, table, index), destructive ones in two deploys; DDL and DML in separate files (a new column can't be updated in the same transaction); `ADD ... DEFAULT x` does not fill existing rows; `ALTER COLUMN ... TYPE ... CHARACTER SET` is silently ignored by Firebird. The database default charset is `ISO8859_1`: declare `CHARACTER SET UTF8` on every new text column. `UPDATE/DELETE ... RETURNING` that matches no row returns a row of NULLs, not `None`: check `linha[0] is None`. Services use `with transacao() as cur:` from `database/db.py`. It commits when the block ends without an exception; otherwise `close()` rolls back and returns the connection to a LIFO pool (max 10). Raw `get_connection()` callers (tests) must commit explicitly and `close()` in `finally`.
- **Auth**: JWT (HS256, `SECRET_KEY`, `exp` 8h) in the `access_token` cookie or `Authorization: Bearer`, created in `services/auth_service.py`. Every check goes through `usuario_do_token`, which also rejects inactive users and tokens issued before `SENHA_ALTERADA_EM` (one query per request). Decorators in `util/usuarios.py`: `usuario_autenticado`, `profissional_autenticado` and `admin_autenticado` pass the decoded payload (`id_usuario`, `usuario_role`) as the first argument. Role checks inside routes read `usuario_role`.
- `funcao.py` holds only pure validators/normalizers (password, CPF, email, phone, name, image, conselho, price, abordagem/modalidade) and the message formatters `formatar_reais` and `formatar_data_hora`. Check it before writing a new one. Other shared helpers: `database.db.nomes_das_colunas(cur)` (cursor columns as JSON keys) and `util/rotas.py` (`sem_cache` for responses with personal data, `MAIOR_ID` as the default `antes` cursor). Email sending (Jinja template `templates/email_codigo.html`) is `services/email_service.py`; `criar_usuario_base` is `services/usuarios_service.py`.
- **Video calls**: WebSocket `/ws/signaling?sessao_id=` (flask-sock), which relays WebRTC offer/answer/ICE. Rooms live **in memory** in `services/signaling_service.py`, and so do the chat connections of `/ws/chat` (`services/chat_service.py`), so the server must run as **one process** (gthread, 32 threads). Don't add workers or switch to gevent: `fdb` uses ctypes and would block the event loop. `GET /api/consultas/<id>/ice-servers` hands out STUN plus temporary Cloudflare TURN credentials (env `TURN_KEY_ID`, `TURN_KEY_API_TOKEN`; STUN only without them).
- **Payments**: `services/pagamentos_service.py` proxies the external Arkhé API (`ARKHE_BASE_URL`, `CLIENT_ID`/`CLIENT_SECRET`) using `urllib`: PIX, boleto and card (`metodo` on `POST /api/pagamentos/cobranca`). Arkhé has no refund or cancel endpoint: refunds (`REEMBOLSO`, created on any cancellation) are paid by an admin through Arkhé outgoing PIX to the CPF key, or marked as paid manually; professional payouts (`REPASSE`, value minus the platform fee and the Arkhé card fee) work the same way. The platform fee depends on the plan active when the charge is created (Essencial 10%, Profissional 8%, Premium 6%, no plan 10%; values in `services/planos_service.py`) and is stored in `PAGAMENTO.TAXA_PLATAFORMA_PERCENTUAL`, so changing plans doesn't touch existing payments; null means an older payment, at 10%. Money rules live in `services/financeiro_service.py`. Its source is public at github.com/GPontin78/back_arkche (`docs/ARQUITETURA_API.md`). Professional subscriptions (`services/assinaturas_service.py`, tables `ASSINATURA`/`COBRANCA_ASSINATURA`) are one Arkhé charge per 30-day cycle, since Arkhé has no recurring billing; the reminders thread also confirms paid charges and sends the renewal PIX. Without a valid plan a professional is hidden from search and can't be booked.
- **Files**: Cloudflare R2 via boto3 (`services/upload_service.py`; env `ENDPOINT_URL`, `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY`, `R2_PUBLIC_URL`, `R2_BUCKET_PRIVADO`). Profile photos (Pillow) go to the public bucket `psicodaily`; anything sensitive (chat attachments) goes to the private bucket `psicodaily-objects` and is read only through `url_assinada` after a participant check.
- **AI assistant**: `POST /api/assistente` runs a tool-calling loop on Gemini's free tier (`gemini-3.5-flash` through its OpenAI-format endpoint, via `urllib`) over existing service functions (`services/assistente_service.py`, env `GEMINI_API_KEY`). It never writes: booking is a proposal the front confirms through `POST /api/consultas`. Tests fake `_chamar`, so CI needs no key.
- **WhatsApp**: own WAHA service on Northflank (`services/whatsapp_service.py`, env `WAHA_URL`, `WAHA_API_KEY`, `WAHA_HMAC_KEY`). Every `notificar` also goes out by WhatsApp; `POST /api/whatsapp/webhook` (HMAC-checked) answers patients with the same assistant. Reminders run in a thread started by `app.py` (`services/lembretes_service.py`); `JOBS=0` disables it and `tests/conftest.py` sets that.
- Frontend origins live in `config.ORIGENS_FRONT`: CORS uses them and every WebSocket handshake must call `origem_permitida()` (`util/usuarios.py`). Add new frontend hosts there.

## Conventions

- Error responses: `raise ErroNegocio(msg, status)` in services; a view may return `jsonify({'error': msg}), status` for request-shape errors.
- Validate request bodies against allowed fields and domain values (see `services/registros_service.py`) and reject unknown fields. Never trust `usuario_id` from the body; take it from the token.
- Commit messages: Conventional Commits in Portuguese (`feat: ...`, `fix: ...`).
- Clean code: descriptive Portuguese names, small functions with one job, no dead code, 4-space indentation. Unpack database rows into named variables (`status, inicio, fim = sessao`), never `sessao[2]`. The team is students and must understand the code it ships.
- Comments (decided 2026-11-09): every file opens with a docstring saying what it does, which routes use it and any new term in one line. Every public function and route gets a short docstring saying what it does (routes: `"""GET /api/...: ..."""`). Inline comments only in the hard parts (locks, Firebird quirks, money math, external APIs, security checks) and they explain how and why, in Portuguese with accents. Never cite internal task codes (`(9)`, `S7`, `F7`) in code: write what they mean. `ponytail:` marks a deliberate shortcut and says its limit and when to improve it.
- Explanations and reports to the team: short. Define every new technical term in one line on first use, or link a source to learn more (MDN, official docs).
